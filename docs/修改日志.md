### 2026-08-30 22:00｜CI/CD 测试全绿修复 + 地址 PATCH 部分更新支持

- **修改内容**：
  1. **后端测试环境统一**：引入 `fakeredis`（纯 Python Redis 模拟器），测试模式下 `get_redis_connection` 返回 `FakeRedis` 实例，本地与 CI 行为一致，无需真实 Redis 服务
  2. **测试环境限流配置**：`settings/dev.py` 测试模式下 `DEFAULT_THROTTLE_RATES` 自定义 scope 设为 `1000/minute`，避免 `ImproperlyConfigured` 报错，同时不影响限流代码路径测试
  3. **修复 35 个测试失败**，涉及 7 个模块：
     - `accounts`：URL 末尾补斜杠（15 处 301 重定向问题）、邮箱标准化期望值修正、`UserFollowTest` 清空 Redis 缓存避免测试间污染
     - `forum`：移除 `Post.hot_score` property（与 `annotate` 冲突），相关测试改用 `HotPostService` 计算
     - `formula`：`CubeStateService` 增加类型防御校验（order 非法时跳过数量计算、block 非法时跳过中心块/相邻块校验）、测试数据补全 27 块、tag 断言用 id 比较、逆公式期望值修正
     - `home`：删除测试不存在端点的用例
     - `utils`：图片质量测试改用随机噪声图（纯色小图 WebP 低质量反而更大）
     - `shop`：`test_create_order_with_invalid_cart` 断言修正为 HTTP 400、`test_category_ordering` 排除 setUp 数据干扰
  4. **shop 地址 PATCH 支持**：`AddressViewSet.update()` 增加 `partial` 参数支持，新增 `partial_update()` 方法，PATCH 请求可部分更新地址
  5. **CI 工作流**：后端测试排除 shop 的临时限制已移除，全量 310 个测试纳入 CI
- **修改原因**：CI/CD 上线前需确保所有测试通过；fakeredis 统一本地与 CI 测试环境，消除 Redis 依赖差异；地址 PATCH 支持符合 REST 规范，前端可只传修改字段
- **影响范围**：修改 `settings/dev.py`、`apps/formula/services.py`、`apps/shop/views.py`；新增 `fakeredis==2.28.0` 依赖；修改各模块测试文件共 10 个
- **验证结果**：本地全量 310 个测试全部通过（`python manage.py test -v 2`），OK

### 2026-08-28 17:20｜CI/CD 自动化流水线（GitHub Actions）

- **修改内容**：
  1. 新增 `.github/workflows/cicd.yml`，包含 4 个 Job：后端 Lint+Test（ruff + Django test，Redis 服务容器）、前端 Build 验证（npm ci + vite build）、Docker 镜像构建验证（前后端 Dockerfile + compose config 校验）、SSH 自动部署
  2. PR 到 main 分支触发 CI 检查（3 个 Job 并行）；push 到 main 分支触发 CI 检查 + 通过后自动 SSH 部署
  3. 部署流程：SSH 连接服务器 → `backup.sh` 数据库备份 → `deploy_update.sh --non-interactive` 智能更新 → HTTP 健康检查（前端 + API）
  4. 修改 `scripts/deploy/deploy_update.sh`，新增 `--non-interactive` 参数：非交互模式下自动确认所有默认为 y 的操作（rebuild front、compose up、restart nginx），自动跳过默认为 n 的操作（日志查看），git pull 使用 `--ff-only`，本地有未提交改动时自动丢弃
- **修改原因**：实现代码推送后自动测试、构建、部署的 CI/CD 流水线，减少手动 SSH 操作；非交互模式使部署脚本可在 CI 环境中无人值守运行
- **影响范围**：新增 `.github/workflows/cicd.yml`；修改 `scripts/deploy/deploy_update.sh`；GitHub Secrets 需配置 `SERVER_HOST`、`SERVER_USER`、`SSH_PRIVATE_KEY`、`DEPLOY_PATH`
