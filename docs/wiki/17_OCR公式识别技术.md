# OCR 公式识别技术

## 1. 背景与目标

ICube 移动端（cube_app）需要从用户拍摄的魔方公式图片中识别出公式文本，填入公式输入框。

**核心挑战**：魔方公式记号（Singmaster notation）包含对 OCR 极不友好的字符：

| 字符类型 | 示例 | OCR 困难点 |
|---------|------|-----------|
| 撇号 `'` | `U'`、`R'` | 极细竖线，易丢失或被误认为 `H`、`/`、`|` |
| 大小写敏感 | `r` vs `R`、`u` vs `U` | Tesseract 倾向输出小写 |
| 括号 `()` | `(U')` | 不在白名单时导致 `(U` 被当成单 blob |
| 换行 | 多行公式 | 需保留为分隔符 |
| token 粘连 | `rU'` → `ru'` | 字符间距小时 Tesseract 合并识别 |

**目标输出**：`U' r U' R' U R U r'`（空格分隔的有效 token 序列）

---

## 2. 技术栈

- **OCR 引擎**：Tesseract.js 5.x（前端 WASM，离线运行）
- **图像处理**：Canvas 2D API（纯浏览器实现，无外部依赖）
- **运行环境**：Capacitor 8 WebView / 浏览器

---

## 3. 整体架构

```
用户裁剪公式区域
       ↓
┌──────────────────────────┐
│  预处理层 preprocessImage │
│  自适应：干净图 / 脏图     │
└──────────┬───────────────┘
           ↓ 预处理后 canvas
┌──────────────────────────┐
│  识别层 multiPassOCR      │
│  并行 5 路识别取最优：     │
│  · PSM 7（单行文本）      │
│  · PSM 8（单字词组）      │
│  · PSM 13（原始行）       │
│  · PSM 6（文本块）        │
│  · seg（投影分割字符级）  │
└──────────┬───────────────┘
           ↓ 每路原始文本
┌──────────────────────────┐
│  后处理层 cleanNotation   │
│  字符映射 → 分割 → 过滤   │
└──────────┬───────────────┘
           ↓
     评分选最优 → 输出
```

## 4. 实现原理

### 4.1 预处理层（preprocessImage）

源文件：[ocr-helper.js](file:///e:/BH/PyStudy/ICube/cube_app/src/utils/ocr-helper.js)

#### 自适应检测

```
放大 4x → 采样灰度 → 判断是否为干净二值图
                        ├─ 是 → 仅白边填充（跳过强预处理）
                        └─ 否 → 完整预处理管线
```

**干净图判据**：灰度值落在 `[0,30]`（黑）或 `[225,255]`（白）的像素占比 > 90%。截图类图片通常满足此条件。

**为什么需要自适应**：对于已经是黑字白底的截图，对比度增强和膨胀操作反而会破坏笔画——膨胀会把撇号 `'` 和相邻字母粘连成 blob，导致 Tesseract 把 `r'` 识别为 `y`。

#### 完整预处理管线（脏图）

```
放大 4x
  → 灰度化（0.299R + 0.587G + 0.114B）
  → 对比度增强（factor=2.0）
  → Otsu 自动阈值二值化
  → 膨胀（3×3 核，加固笔画）
  → 白边填充（10% 宽度）
```

| 步骤 | 作用 | 关键参数 |
|------|------|---------|
| 放大 | 让细字符（撇号）有足够像素 | `scale=4` |
| 灰度化 | 统一色彩通道 | Rec. 601 加权 |
| 对比度增强 | 拉开前景与背景 | `contrast=2.0` |
| Otsu 二值化 | 自动找最佳阈值 | 类间方差最大化 |
| 膨胀 | 加固细笔画 | 3×3 核 × 1 次 |
| 白边填充 | Tesseract 对有边距图识别更好 | `max(20, 10%×宽)` |

### 4.2 识别层（multiPassOCR）

#### 多轮 PSM 识别

使用 Tesseract 的不同 Page Segmentation Mode 并行识别：

| PSM | 模式 | 适用场景 |
|-----|------|---------|
| 7 | 单行文本 | 公式在一行内 |
| 8 | 单字词组 | 稀疏字符 |
| 13 | 原始行 | 保留原始分行 |
| 6 | 文本块 | 多行公式 |

**参数配置**：
```javascript
{
  tessedit_char_whitelist: "RLUDFBMESxyzrludfb'2() ",  // 白名单含括号和撇号
  tessedit_ocr_engine_mode: '2',                        // LSTM 引擎
  preserve_interword_spaces: '1',                       // 保留空格
  user_defined_dpi: '300',                              // 声明 DPI
}
```

#### 投影分割字符级识别（segmentAndRecognize）

这是解决撇号丢失问题的**核心方案**。

```
预处理后 canvas
  ↓
二值化（gray < 128 → 黑）
  ↓
行投影：统计每行黑像素数 → 分割出文本行
  ↓
列投影：统计每列黑像素数 → 分割出字符
  ↓
每个字符单独裁剪 + 15px 白边
  ↓
PSM 10（单字符模式）逐个识别
  ↓
合并结果
```

**为什么有效**：
- 整图识别时 Tesseract 把 `r U'` 当成一个 blob → `ru'`（撇号粘连）
- 投影分割后每个字符独立识别，撇号不会和字母合并
- PSM 10 模式专门为单字符优化，识别率更高

### 4.3 后处理层（cleanNotation）

#### 字符映射修正

Tesseract 对特定字符有固定的误认模式，通过映射表修正：

| 误认字符 | 实际字符 | 误认原因 |
|---------|---------|---------|
| `/` | `'` | 撇号被识别为斜杠 |
| `\|` | `'` | 撇号被识别为竖线 |
| `H` | `'` | 撇号被识别为 H |
| `I` | `r` | 小写 r 被识别为大写 I |
| `W` | 删除 | 括号 `(` 被识别为 W |
| `′ʼ\`´’` | `'` | 各种 Unicode 撇号变体 |

#### 删除无关字符

```javascript
// 删除所有中英文括号
cleaned.replace(/[()（［【〕】｝〉>]/g, ' ')
// 删除换行和回车（作为分隔符而非直接删除）
cleaned.replace(/[\n\r]/g, ' ')
```

**换行处理为空格而非删除**：因为 `\n` 若直接删除会把相邻 token 粘连成无效串（如 `U'\nR'` → `U'R'`），必须当作分隔符处理。

#### Token 分割

```javascript
// 有效 token 模式：字母 + 可选撇号或数字2
const validPattern = /^[RLUDFBMESxyzrludfb]['2]?$/
```

长度 > 2 的 token 按字符逐个拆分，遇到 `'` 或 `2` 则与前一个字符合并：

```
ru' (3字符) → [r, u']
LU  (2字符) → [L, U]
```

#### 评分机制

```
评分 = 置信度 × max(1, 有效 token 数)
```

- 偏好高置信度和多有效字符的结果
- 投影分割识别（seg）固定置信度 80，靠有效 token 数竞争

## 5. 逐步优化过程

### 第一版：基础识别

**初始状态**：简单白名单 + PSM 7 单轮识别

```javascript
tessedit_char_whitelist: "RLUDFBMESxyzrludfb'2 ",
```

**问题**：白名单**不含括号 `()`**，导致 `(U)` 中的 `(` 不在白名单，Tesseract 把 `(U` 当成一个 blob → 输出 `Dry`。

### 第二版：多轮 PSM + 清洗

**改动**：
1. 加入 PSM 7/8/13/6 四轮识别取最优
2. cleanNotation 删除括号和换行
3. 评分 = 置信度 × 有效 token 数

**问题**：仍然无法识别撇号，`U'` → `U`，因为白名单不含括号导致 blob 合并。

### 第三版：白名单加入括号

**改动**：
```javascript
tessedit_char_whitelist: "RLUDFBMESxyzrludfb'2() ",
```

**问题**：撇号仍然丢失。Tesseract 在整图识别时把 `r U'` 合并为 `ru'`，撇号与字母粘连。

### 第四版：移除白名单 + LSTM

**改动**：移除 `tessedit_char_whitelist`，改用 LSTM 引擎自由识别。

**问题**：LSTM 太自由，撇号丢失更严重（`U'` → `U`），且输出不可控。

### 第五版：恢复白名单 + 4x 放大 + DPI

**改动**：
1. 恢复白名单（含括号和撇号）
2. 放大倍数 3x → 4x（让撇号有更多像素）
3. 加入 `user_defined_dpi: '300'`

**结果**：撇号偶尔出现（`ru'`），但 token 粘连严重。

### 第六版：自适应预处理

**改动**：
1. 检测图片是否为干净二值图（黑字白底）
2. 干净图跳过对比度/二值化/膨胀，仅放大 + 白边填充

**问题**：膨胀操作对干净图有害——把撇号和字母粘连。自适应跳过解决了膨胀破坏问题，但撇号仍被识别为 `H` 或 `/`。

### 第七版：投影分割字符级识别（关键突破）

**改动**：新增 `segmentAndRecognize` 函数
1. 行投影分割文本行
2. 列投影分割字符
3. PSM 10 单字符模式逐个识别

**结果**：撇号不再与字母粘连。但 Tesseract 把撇号识别为 `/`，把小写 r 识别为 `I`。

### 第八版：字符映射修正（最终版）

**改动**：在 cleanNotation 中加入误认映射：

```javascript
cleaned.replace(/[/|]/g, "'")   // 撇号误认为斜杠/竖线
cleaned.replace(/H/g, "'")       // 撇号误认为 H
cleaned.replace(/I/g, 'r')      // 小写 r 误认为大写 I
cleaned.replace(/W/g, ' ')       // 括号 ( 误认为 W，删除
```

**验证结果**：
```
输入: (U/)rU/R/URU\nI/\n
清洗: U' r U' R' U R U r'  ✓ 完全匹配目标
```

## 6. 优化决策总结

| 优化点 | 解决的问题 | 为什么这样做 |
|--------|-----------|------------|
| 自适应预处理 | 膨胀破坏干净图笔画 | 干净图已二值化，不需要再处理 |
| 白名单含括号 `()` | `(U` 被合并为 blob | 让 Tesseract 正确分词 |
| 4x 放大 | 撇号像素不足 | 3x 下撇号仅 1-2px，Tesseract 忽略 |
| LSTM 引擎 | 大小写不分 | LSTM 比传统统计模型对大小写更敏感 |
| 投影分割识别 | token 粘连 | 逐字符识别，避免 blob 合并 |
| `/→'` 映射 | 撇号被识别为斜杠 | Tesseract 对细竖线的固定误认 |
| `I→r` 映射 | 小写 r 被识别为 I | 视觉相似性导致的固定误认 |
| 换行→空格 | token 跨行粘连 | 删除会粘连，空格保持分隔 |
