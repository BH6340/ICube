# 智能魔方功能实现详解

***

## 1. 功能概述

### 1.1 功能定位与使用场景

智能魔方是 ICube 平台的核心差异化功能之一，支持用户通过蓝牙连接 GAN 品牌智能魔方，实现自动打乱、实时计时、3D 姿态跟随、转动序列记录和复原检测，替代传统手动秒表计时方式。

**使用场景**：

- 用户在 Web 端（Chrome/Edge）通过 Web Bluetooth API 连接 GAN 智能魔方
- 系统自动生成 WCA 风格打乱序列，用户按序列拨动魔方完成打乱
- 打乱完成后进入观察阶段（标准模式 15 秒倒计时），首次转动开始计时
- FACELETS 事件检测到复原状态后自动停止计时，记录用时、步数、打乱序列
- 3D 魔方实时同步转动，陀螺仪模式下姿态跟随真实魔方

### 1.3 与手动计时器的关系

平台同时支持手动计时和智能计时两种模式：

| 维度 | 手动计时 | 智能魔方计时 |
|------|---------|-------------|
| 入口 | TimerView（`/timer`） | TimerView 智能模式 / SmartCubeView（`/smart-cube`） |
| 触发方式 | 长按/松手 | BLE 事件自动驱动 |
| 打乱 | 系统生成文本 | 系统生成序列 + 用户按序列拨动校验 |
| 计时精度 | 手动反应时间 | BLE 事件时间戳 |
| 复原检测 | 无 | FACELETS 自动检测 |
| 步数记录 | 无 | MOVE 事件自动计数 |
| 设备关联 | 无 | SmartCubeDevice |
| 移动端支持 | 是 | 暂未接入 |

`/smart-cube` 路由重定向到 `/timer?mode=smart`，两者共享同一套后端 API。

## 2. BLE 连接与 GAN Gen4 协议

### 2.1 Web Bluetooth API 前置条件

Web Bluetooth API 是浏览器原生蓝牙通信接口，有以下硬性要求：

- **浏览器**：仅 Chrome（56+）、Edge（79+）支持，Firefox/Safari 不支持
- **环境**：必须 HTTPS 或 localhost，否则 `navigator.bluetooth` 为 undefined
- **用户交互**：`requestDevice()` 必须由用户手势（点击）触发，不能自动调用
- **权限**：用户需在弹出的设备选择器中手动选择目标设备

项目通过 Cloudflare Tunnel 将域名 `bh6340.me` 接入 HTTPS，满足 Web Bluetooth 环境要求。

支持检测：

```javascript
static get isSupported() {
  return typeof navigator !== 'undefined' && !!navigator.bluetooth
}
```

### 2.2 设备发现与名称过滤

`requestDevice()` 通过名称前缀过滤 GAN 系列智能魔方：

```javascript
this._device = await navigator.bluetooth.requestDevice({
  filters: [
    { namePrefix: 'GAN' },
    { namePrefix: 'MG' },
    { namePrefix: 'AiCube' }
  ],
  optionalServices: [SERVICES.GEN4, SERVICES.GEN3, SERVICES.GEN2],
  optionalManufacturerData: CIC_LIST
})
```

- `GAN`：GAN 标准系列（如 GAN 356 i2/i3/i4）
- `MG`：魔域智能系列（部分型号使用 GAN 协议）
- `AiCube`：AiCube 系列
- `optionalServices`：声明可能使用的三代服务 UUID，避免后续 GATT 访问被拒绝
- `optionalManufacturerData`：GAN 厂商 CIC 列表（256 个 `(i << 8) | 0x01`），用于 manufacturer data 过滤和 MAC 地址提取

### 2.3 MAC 地址获取

MAC 地址是 AES 加密 salt 的来源，必须正确获取才能解密魔方通信数据。

**自动获取**：通过 `watchAdvertisements()` 监听广播包，从 manufacturer data 的最后 6 字节倒序提取：

```javascript
async _autoRetrieveMac() {
  // 监听广播，10 秒超时
  return new Promise(resolve => {
    const onAdv = (evt) => {
      const mac = this._extractMac(evt.manufacturerData)
      finish(mac || null)
    }
    this._device.addEventListener('advertisementreceived', onAdv)
    this._device.watchAdvertisements({ signal: controller.signal })
    timer = setTimeout(() => finish(null), 10000)
  })
}
```

**手动输入回退**：`watchAdvertisements` 不支持或超时失败时，通过 `onMacAddressRequired` 回调弹出对话框，由用户手动输入 MAC 地址（格式 `XX:XX:XX:XX:XX:XX`）。页面提供 `edge://bluetooth-internals/#devices` 查看指引。

### 2.4 GATT 服务与特征值

GAN 智能魔方按代际使用不同的 BLE 服务和特征值：

| 代际 | 服务 UUID | 写特征（CMD） | 通知特征（STATE） |
|------|----------|--------------|-------------------|
| Gen2 | `6e400001-...` | `28be4a4a-...` | `28be4cb6-...` |
| Gen3 | `8653000a-...` | `8653000c-...` | `8653000b-...` |
| Gen4 | `00000010-...` | `0000fff5-...` | `0000fff6-...` |

当前实现以 Gen4 为主（最新型号），在 `_setupService()` 中遍历 GATT 服务列表匹配 Gen4 服务 UUID，找到后获取写特征和通知特征。

**通知监听**：

```javascript
this._stateChar.addEventListener('characteristicvaluechanged', this._onStateUpdate)
await this._stateChar.startNotifications()
```

每次收到通知，`_onStateUpdate` 回调被触发，数据经解密后交给协议驱动解析。

### 2.5 连接稳定性设计

BLE 连接存在多种不稳定场景，代码实现了多层防护机制：

**超时机制**：

```javascript
_withTimeout(promise, ms = 8000) {
  return Promise.race([
    promise,
    new Promise((_, reject) => setTimeout(() => reject(new Error('操作超时')), ms))
  ])
}
```

不同操作使用不同超时阈值：

| 操作 | 超时 | 原因 |
|------|------|------|
| `gatt.connect()` | 8s | 适配器忙时可能 hang 住，既不 resolve 也不 reject |
| `getPrimaryServices()` | 8s | 连接不稳定时可能失败 |
| `getCharacteristic()` | 5s | 相对轻量 |
| `startNotifications()` | 5s | 相对轻量 |

**递增重试**：`_connectAndSetupWithRetry()` 重试整个 connect → getServices → setup 流程，间隔 500ms → 1000ms → 1500ms，共 4 次尝试：

```javascript
const delays = [500, 1000, 1500]
for (let i = 0; i <= delays.length; i++) {
  try {
    if (this._device?.gatt?.connected) {
      this._device.gatt.disconnect()
      await new Promise(r => setTimeout(r, 300))  // 等待彻底断开
    }
    await this._withTimeout(this._device.gatt.connect(), 8000)
    await this._setupService(this._device.gatt, salt)
    return
  } catch (err) {
    lastErr = err
    if (i < delays.length) await new Promise(r => setTimeout(r, delays[i]))
  }
}
```

**防重入**：`_connecting` 标志防止用户多次点击连接按钮导致竞态：

```javascript
if (this._connecting) return
this._connecting = true
try { ... } finally { this._connecting = false }
```

**自动重连**：页面加载时调用 `tryAutoReconnect()`，从 localStorage 读取上次设备名和 MAC，通过 `navigator.bluetooth.getDevices()` 查找已授权设备，匹配后静默重连：

```javascript
export async function tryAutoReconnect() {
  const saved = _loadSavedDevice()
  if (!saved) return false
  const client = getCubeClient()
  if (!client._mac) client._mac = saved.mac
  if (!client._name) client._name = saved.name
  const devices = await navigator.bluetooth.getDevices()
  const match = devices.find(d => d.name === saved.name)
  if (!match) return false
  client._device = match
  await client._reconnect()
  return true
}
```

**断开后等待**：`_reconnect()` 在重连前先 disconnect 并等待 500ms，给 BLE 适配器释放时间：

```javascript
async _reconnect() {
  if (this._device?.gatt?.connected) {
    try { this._device.gatt.disconnect() } catch {}
    await new Promise(r => setTimeout(r, 500))
  }
  await this._connectAndSetupWithRetry()
}
```

## 3. AES-128-CBC 加密与数据解密

### 3.1 密钥派生流程

GAN 智能魔方使用 AES-128-CBC 加密 BLE 通信数据。加密密钥由固定密钥和设备 MAC 地址共同派生，确保每台设备通信不可被其他设备解密。

```
┌─────────────┐     ┌──────────────┐
│ 固定 key[16]│     │ 固定 iv[16]   │
│ (代码常量)   │     │ (代码常量)    │
└──────┬──────┘     └──────┬───────┘
       │                   │
       │  前6字节与salt运算  │  前6字节与salt运算
       ▼                   ▼
┌─────────────┐     ┌──────────────┐
│ 实际 key[16]│     │ 实际 iv[16]   │
│ key[i]+salt │     │ iv[i]+salt   │
│ i∈[0,6)     │     │ i∈[0,6)      │
│ mod 0xFF    │     │ mod 0xFF     │
└─────────────┘     └──────────────┘
```

salt 来源：MAC 地址按 `:` 或 `-` 分割为 6 个十六进制字节，**倒序**排列：

```javascript
const salt = new Uint8Array(
  this._mac.split(/[:-\s]+/).map(c => parseInt(c, 16)).reverse()
)
```

### 3.2 加解密实现细节

`CubeEncrypter` 使用 `aes-js` 库实现 AES-128-CBC。加解密策略为分块处理（首块 + 尾块），而非整包一次性处理：

**解密**（接收数据时）：

```javascript
decrypt(data) {
  const res = new Uint8Array(data)
  if (res.length > 16) this._processChunk(res, res.length - 16, false) // 先解尾块
  this._processChunk(res, 0, false)                                    // 再解首块
  return res
}
```

**加密**（发送命令时）：

```javascript
encrypt(data) {
  const res = new Uint8Array(data)
  this._processChunk(res, 0, true)           // 先加密首块
  if (res.length > 16) this._processChunk(res, res.length - 16, true) // 再加密尾块
  return res
}
```

每块使用独立的 CBC 实例处理，前 6 字节被 salt 修正：

```javascript
constructor(key, iv, salt) {
  this._key = new Uint8Array(key)
  this._iv = new Uint8Array(iv)
  for (let i = 0; i < 6; i++) {
    this._key[i] = (key[i] + salt[i]) % 0xFF
    this._iv[i] = (iv[i] + salt[i]) % 0xFF
  }
}
```

### 3.3 安全考量

- 固定密钥和 IV 硬编码在前端代码中，可通过浏览器 DevTools 查看源码获取
- 加密强度有限（仅前 6 字节受 MAC salt 影响），主要目的是设备配对隔离而非通信安全
- 对于学习平台场景（非金融/隐私数据），此安全级别可接受

## 4. 协议事件解析

### 4.1 事件类型总览

Gen4 协议的 State Characteristic 通知数据解密后，按 `[eventType(1B)] [dataLength(1B)] [data...]` 格式解析。一个通知包可能包含多个事件拼接。

| 事件 | 类型码 | 固定长度 | 含义 |
|------|--------|---------|------|
| MOVE | `0x01` | 9B | 魔方转动 |
| GYRO | `0xEC` | 12B | 陀螺仪数据（四元数+速度） |
| FACELETS | `0xED` | 16B | 魔方状态快照（角块/边块位置与朝向） |
| DISCONNECT | `0xEA` | 2B | 断开通知 |
| BATTERY | `0xEF` | 4B | 电量百分比 |
| MOVE_HISTORY | `0xD1` | - | 历史转动记录 |
| PRODUCT_DATE | `0xFA` | - | 生产日期 |
| HARDWARE_NAME | `0xFC` | 10B | 硬件名称 |
| SOFTWARE_VERSION | `0xFD` | 10B | 软件版本 |
| HARDWARE_VERSION | `0xFE` | 10B | 硬件版本 |

多事件解析循环中，优先使用 `dataLength` 推进偏移量；`dataLength=0` 或越界时回退到固定长度表；两者都无法确定时跳出循环避免死循环。

### 4.2 MOVE 事件解析

MOVE 事件携带一次转动的完整信息：

```
偏移    位长度    字段            说明
0-15    16B       (事件头)        eventType + dataLength
16-47   32b       cubeTimestamp   魔方内部时间戳（小端序）
48-63   16b       serial          转动序号（小端序）
64-65   2b        direction       方向：0=顺时针，1=逆时针
66-71   6b        faceBitmask     面位掩码
```

面位掩码到面名的映射：

```javascript
const FACE_BITMASKS = [2, 32, 8, 1, 16, 4]  // U, R, F, D, L, B
const FACE_NAMES = 'URFDLB'
const face = FACE_BITMASKS.indexOf(faceBitmask)
const move = FACE_NAMES.charAt(face) + (direction ? "'" : '')
```

解析结果示例：`{ type: 'MOVE', move: "R'", face: 1, direction: 1, serial: 42, cubeTimestamp: 123456 }`

### 4.3 FACELETS 事件解析

FACELETS 事件包含魔方的完整状态快照，使用角块-边块（CP/CO/EP/EO）编码：

```
偏移     位长度    字段            说明
0-15     16B       (事件头)
16-31    16b       serial          状态序号
32-52    7×3b      cp[0..6]        7 个角块位置（第 8 个由校验和推导）
53-66    7×2b      co[0..6]        7 个角块朝向（第 8 个由校验和推导）
69-112   11×4b     ep[0..10]       11 个边块位置（第 12 个由校验和推导）
113-123  11×1b     eo[0..10]       11 个边块朝向（第 12 个由校验和推导）
```

第 8 个角块和第 12 个边块通过校验和推导：

```javascript
cp.push(28 - cp.reduce((a, v) => a + v, 0))
co.push((3 - (co.reduce((a, v) => a + v, 0) % 3)) % 3)
ep.push(66 - ep.reduce((a, v) => a + v, 0))
eo.push((2 - (eo.reduce((a, v) => a + v, 0) % 2)) % 2)
```

复原检测：所有角块在原位且朝向为 0，所有边块在原位且朝向为 0：

```javascript
const isSolved = cp.every((v, i) => v === i) &&
  co.every(v => v === 0) &&
  ep.every((v, i) => v === i) &&
  eo.every(v => v === 0)
```

### 4.4 GYRO 事件解析

GYRO 事件包含四元数和角速度：

```
偏移    位长度    字段        说明
16-31   16b       qw          四元数 w 分量（定点数）
32-47   16b       qx          四元数 x 分量
48-63   16b       qy          四元数 y 分量
64-79   16b       qz          四元数 z 分量
80-83   4b        vx          x 轴角速度
84-87   4b        vy          y 轴角速度
88-91   4b        vz          z 轴角速度
```

定点数转浮点数：

```javascript
const toFloat = (raw) => (1 - (raw >> 15) * 2) * (raw & 0x7FFF) / 0x7FFF
```

最高位为符号位，低 15 位为幅值，归一化到 `[-1, 1]`。

### 4.5 MOVE 缓冲机制

协议驱动中实现了 MOVE 事件缓冲机制：MOVE 事件先暂存到 `_moveBuffer`，FACELETS 事件到达后优先输出缓冲区中的所有 MOVE，再输出 FACELETS：

```javascript
if (eventType === EventType.MOVE) {
  const move = this._parseMove(msg, timestamp)
  if (move) this._moveBuffer.push(move)
} else if (eventType === EventType.FACELETS) {
  const facelets = this._parseFacelets(msg, timestamp)
  if (facelets) {
    while (this._moveBuffer.length > 0) {
      events.push(this._moveBuffer.shift())  // 先输出缓冲的 MOVE
    }
    events.push(facelets)                     // 再输出 FACELETS
  }
}
```

安全阀：缓冲区超过 50 条时强制输出，防止 FACELETS 事件丢失导致缓冲区无限增长。

## 5. 计时器状态机

### 5.1 状态流转

```
         来回拨动              按序列转动完          首次转动
IDLE ──────────▶ SCRAMBLING ────────▶ OBSERVATION ────────▶ SOLVING
 ▲                                          │                  │
 │                                          │ 超时(DNF)         │ 检测复原
 │              来回拨动                     ▼                  ▼
 └──────────────────────────────────── SOLVED ◀─────────────────
```

| 状态 | 值 | 触发条件 | 行为 |
|------|---|---------|------|
| IDLE | `idle` | 初始/重置 | 等待来回拨动（如 R R'）触发打乱 |
| SCRAMBLING | `scrambling` | IDLE 检测到来回拨动 | 生成打乱序列，逐步校验用户转动 |
| OBSERVATION | `observation` | 打乱序列完成 | 15 秒倒计时（标准模式）/ 不限时（不计时模式） |
| SOLVING | `solving` | 观察阶段首次转动 | 计时开始，记录 MOVE 和步数 |
| SOLVED | `solved` | FACELETS 检测复原 / 观察超时 | 记录结果，等待新一轮来回拨动 |

### 5.2 WCA 风格打乱生成算法

```javascript
function generateScramble(length = 20) {
  const sequence = []
  let lastFace = null
  let lastLastFace = null

  while (sequence.length < length) {
    const face = FACES[Math.floor(Math.random() * 6)]
    if (face === lastFace) continue                                    // 不连续同面
    if (face === lastLastFace && OPPOSITE[face] === lastFace) continue // 不连续对面
    const dir = Math.random() < 0.5 ? '' : "'"
    sequence.push(face + dir)
    lastLastFace = lastFace
    lastFace = face
  }
  return sequence
}
```

规则：

1. **不连续同面**：如 `R` 后不能直接 `R` 或 `R'`，避免冗余转动
2. **不连续对面**：如 `R` 后不能直接 `L`（`R L` 等效于 `R R` 对面的联动），避免冗余
3. **方向随机**：正转（`R`）或逆转（`R'`）各 50% 概率
4. **长度**：默认 20 步（WCA 三阶标准打乱长度）

### 5.3 标准模式 vs 不计时模式

| 维度 | 标准模式（practice） | 不计时模式（unlimited） |
|------|---------------------|----------------------|
| 观察时间 | 15 秒倒计时 | 不限时 |
| 超时处理 | 判 DNF | 15 秒后从 0 开始正计时 |
| 显示内容 | 剩余倒计时 | 已用观察时间 |
| 适用场景 | 正式训练/模拟比赛 | 自由练习 |

标准模式超时判 DNF：

```javascript
if (this._mode === 'practice' && remaining <= 0) {
  this._lastResult = {
    solveTime: null,
    solveTimeFormatted: 'DNF',
    dnf: true,
    // ...
  }
  this._callbacks.onSolveComplete(this._lastResult)
}
```

### 5.4 打乱进度与错误处理

打乱阶段用户按序列逐步转动，系统实时校验：

**正确步骤**：推入栈，步数 +1，打乱完成后进入观察阶段。

**分支回退**：用户做了上一步的逆（如已完成 `R`，又做 `R'`），出栈回退：

```javascript
if (move === inverseMove(this._scrambleStack[this._scrambleStack.length - 1])) {
  const undone = this._scrambleStack.pop()
  this._scrambleStep--
  this._scrambleSequence.splice(this._scrambleStep, 1) // 移除当前 expected
}
```

**错误步骤**：在当前位置前插入逆步骤，提示用户先回退再做原步骤：

```javascript
const invMove = inverseMove(move)
this._scrambleSequence.splice(this._scrambleStep, 0, invMove) // 插入逆步骤
this._callbacks.onWarning(`步骤错误：${move}，请做 ${invMove} 回退`)
```

打乱进度通过 chip 组件可视化，已完成步数绿色、当前步数橙色、待完成步数灰色。

## 6. 持握方向与转体检测

### 6.1 陀螺仪模式

陀螺仪模式通过 GYRO 事件自动识别用户持握方向，建立内部面到用户面的映射。

**流程**：

1. 连接后开始接收 GYRO 数据
2. 用四元数旋转向量，找到朝上（z 分量最大）的内部面 → `topFace`
3. 弹出朝前面选择器，排除顶面和底面，用户从剩余 4 面中选择朝前面的内部面
4. 调用 `setInitialMap(topFace, frontFace)` 锁定映射，此后所有 MOVE 事件走这套映射

**顶面检测**：

```javascript
_detectTopFace(q) {
  let topFace = null, topDot = -2
  for (const face of FACES) {
    const rotated = rotateVector(q, FACE_NORMALS[face])
    if (rotated[2] > topDot) {
      topDot = rotated[2]
      topFace = face
    }
  }
  this._onTopFaceDetected?.(topFace)
}
```

**映射建立**：由顶面和前面推导完整 6 面映射，使用点积匹配找到每个内部面对应的用户面，符号判断是否需要反转方向：

```javascript
function buildStaticMap(topFace, frontFace) {
  const topVec = FACE_NORMALS[topFace]
  const frontVec = FACE_NORMALS[frontFace]
  const rightVec = cross(topVec, frontVec) // 右手坐标系叉乘
  // 6 个用户轴：up/down/front/back/right/left
  // 遍历 6 个内部面，找到点积最大的用户轴
  // bestDot < 0 表示方向相反，需要 invert
}
```

### 6.2 经典模式

用户从 6 种预设持握方向中选择，无需陀螺仪数据：

| 预设 | 顶面 | 前面 | 说明 |
|------|------|------|------|
| 白顶绿前（标准） | U | F | 最常见持握 |
| 白底绿前 | D | F | 底白持握 |
| 白顶红前 | U | R | 红色朝前 |
| 白底红前 | D | R | 底白红前 |
| 白顶蓝前 | U | B | 蓝色朝前 |
| 白顶橙前 | U | L | 橙色朝前 |

所有预设映射在模块加载时预计算缓存：

```javascript
const PRESET_MAPS = {}
for (const preset of PRESET_ORIENTATIONS) {
  PRESET_MAPS[preset.key] = buildStaticMap(preset.top, preset.front)
}
```

### 6.3 MOVE 重映射机制

`remapMove()` 将魔方内部记号转换为用户视角记号：

```javascript
function remapMove(move, ctx) {
  if (!ctx) return move              // 无映射上下文 = 标准持握
  const face = move[0]
  const isPrime = move.includes("'")
  const entry = ctx[face]
  if (!entry) return move
  const dir = isPrime ? !entry.invert : entry.invert
  return entry.face + (dir ? "'" : '')
}
```

映射上下文是一个对象 `{ 内部面: { face: 用户面, invert: 是否反转 } }`，例如内部 R 面对应用户 L 面且需要反转时，`R` → `L'`，`R'` → `L`。

### 6.4 转体检测参数

陀螺仪模式持续检测用户转体（x/y/z 旋转），使用双角度稳定判定状态机：

| 参数 | 值 | 作用 |
|------|---|------|
| 累积角度阈值 `ROTATION_THRESHOLD` | 40° | 累积旋转超过此值才判定为有效转体 |
| 帧间增量阈值 `MOTION_THRESHOLD` | 5° | 帧间变化超过此值认为"还在动" |
| 稳定判定时间 `SETTLE_TIME` | 250ms | 持续无大动作多久才判定为"停下来了" |

状态流转：

```
IDLE → 增量 > 5° → MOVING
MOVING → 增量 < 5° 且持续 250ms → 已稳定
  → 累积 > 40° → emit 转体 → IDLE
  → 累积 < 40° → 微调，IDLE
```

转体类型判定基于旋转轴的最大分量：

- 世界 X 轴 → `x`（前后翻）
- 世界 Z 轴 → `y`（左右转）
- 世界 Y 轴 → `z`（侧翻）

方向规则（实测校准）：

```javascript
const isPrime = axisName === 'z'
  ? (direction * quarters) < 0
  : (direction * quarters) > 0
```

## 7. 3D 魔方渲染

### 7.1 双层架构

Cube3D 组件采用双层 Group 架构，分离姿态跟随和层转动两个职责：

```
scene
  └─ outerGroup          ← 整体姿态（陀螺仪跟随 / 经典模式预设）
       └─ cubeGroup      ← 层转动（MOVE 事件驱动）
            └─ 27 × Mesh ← 3×3×3 小方块
```

- `outerGroup`：只接收陀螺仪四元数或经典模式预设姿态，不被 MOVE 影响
- `cubeGroup`：只接收层转动动画，不被姿态影响
- 两者解耦后，转动动画在 `cubeGroup` 局部坐标系中计算，不受 `outerGroup` 旋转影响

### 7.2 转动队列与动画

转动使用队列模式，动画中自动排队，空闲即播：

```javascript
function processQueue() {
  if (isAnimating) return
  if (moveQueue.length === 0) return
  isAnimating = true
  const next = moveQueue.shift()
  executeRotation(next, props.animationSpeed).then(() => {
    isAnimating = false
    emit('moveCompleted', next)
    processQueue()
  })
}
```

单步转动动画使用 `@tweenjs/tween.js` 的 Quadratic.Out 缓动：

```javascript
new Tween(animState, tweenGroup)
  .to({ currentAngle: angle }, duration)
  .easing(Easing.Quadratic.Out)
  .onUpdate(() => {
    const delta = animState.currentAngle - lastAngle
    lastAngle = animState.currentAngle
    movingCubes.forEach(mesh => rotateMeshAroundLocalAxis(mesh, axis, delta))
  })
```

记号解析（`parseNotation`）支持 R/L/U/D/F/B 及其逆、双层（r/l/u/d/f/b）、中层（M/E/S）和转体（x/y/z），每种记号对应一个旋转轴和筛选条件。

### 7.3 陀螺仪姿态跟随

陀螺仪模式下，`setAttitude()` 接收 GAN 坐标系四元数，映射到 Three.js 坐标系后设置到 `outerGroup`：

```javascript
setAttitude(quat) {
  // GAN 坐标系 → Three.js 坐标系：
  //   GAN X（R-L 轴）→ Three X（同轴）
  //   GAN Z（U-D 轴）→ Three Y（同轴）
  //   GAN Y（F-B 轴）→ -Three Z（方向取反：GAN +Y=B 而 Three +Z=F）
  outerGroup.quaternion.set(quat.x, quat.z, -quat.y, quat.w)
}
```

SmartCubeView 中计算相对初始姿态的旋转 `relQuat = currentQuat × baseQuat⁻¹`，确保 3D 魔方从用户确认朝向时的位置开始跟随。

GYRO 事件通过 `requestAnimationFrame` 合合同帧多次更新为一次，减少渲染压力：

```javascript
if (!gyroRafId) {
  gyroRafId = requestAnimationFrame(() => {
    gyroRafId = null
    if (pendingGyroQuat) {
      updateCubeAttitude(pendingGyroQuat)
      pendingGyroQuat = null
    }
  })
}
```

### 7.4 性能优化

**共享资源**：27 个小方块共享 1 份 `BoxGeometry`、1 份 `EdgesGeometry`、7 个 `MeshPhysicalMaterial`（6 面 + 内部黑色），而非每块各创建一套：

```javascript
const _rotAxis = new THREE.Vector3()
const _rotMatrix = new THREE.Matrix4()
const _rotQuat = new THREE.Quaternion()
```

**按需渲染**：无动画、无交互、无姿态更新时跳过 `renderer.render()`：

```javascript
if (tweenGroup.getAll().length > 0) needsRender = true
if (needsRender) {

```

## 8. 2D 状态模拟与展开图

### 8.1 面旋转算法

cube-state.js 实现了 3x3 魔方的 2D 状态模拟，每个面用长度为 9 的数组表示，6 个面顺序为 U/R/F/D/L/B。

每种转动包含两个操作：
1. **面旋转**：被转面自身的 90° 旋转（`rotateFaceCW` / `rotateFaceCCW` / `rotateFace180`）
2. **边轮换**：相邻 4 个面的边贴纸按特定方向轮换

以 R 转动为例：

```javascript
function moveR(state) {
  state[R] = rotateFaceCW(state[R])  // R 面自身顺时针 90°
  // 影响的边贴纸：U 右列 → F 右列 → D 右列 → B 左列(反向) → U 右列
  const uCol = [state[U][2], state[U][5], state[U][8]]
  const fCol = [state[F][2], state[F][5], state[F][8]]
  const dCol = [state[D][2], state[D][5], state[D][8]]
  const bCol = [state[B][6], state[B][3], state[B][0]]  // B 面左列反向

  state[F][2] = uCol[0]; state[F][5] = uCol[1]; state[F][8] = uCol[2]
  state[D][2] = fCol[0]; state[D][5] = fCol[1]; state[D][8] = fCol[2]
  state[B][6] = dCol[0]; state[B][3] = dCol[1]; state[B][0] = dCol[2]
  state[U][2] = bCol[0]; state[U][5] = bCol[1]; state[U][8] = bCol[2]
}
```

逆转动 = 连续 3 次正转，180° = 连续 2 次正转：

```javascript
"R'": (s) => { moveR(s); moveR(s); moveR(s) },
'R2': (s) => { moveR(s); moveR(s) },
```

支持的全部记号：R/R'/R2、L/L'/L2、U/U'/U2、D/D'/D2、F/F'/F2、B/B'/B2。不处理 r/l/u/d/f/b/M/E/S 等内层记号。

## 11. 移动端现状与规划

### 11.1 Capacitor 配置

```json
{
  "appId": "com.icube.app",
  "appName": "ICube",
  "webDir": "dist",
  "server": {
    "cleartext": true,
    "androidScheme": "http"
  }

```

- `androidScheme: "http"`：Capacitor 6+ 默认用 `https://localhost` 加载 WebView，会拦截 HTTP 请求，改为 http 协议
- `cleartext: true`：允许明文流量（配合 `network_security_config.xml`）

### 11.2 移动端计时器

移动端 `cube_app/src/views/TimerView.vue` 是手动计时器页面：

- 长按/松手触发计时
- 历史记录保存到 `localStorage`
- 登录后同步后端 `/api/timer/records/`
- 后端加载失败时降级到本地记录

### 11.3 BLE 权限缺失现状与接入规划

当前 `AndroidManifest.xml` 仅声明 `INTERNET` 权限，缺少蓝牙相关权限：

```xml
<!-- 缺少的权限 -->
<uses-permission android:name="android.permission.BLUETOOTH" />
<uses-permission android:name="android.permission.BLUETOOTH_ADMIN" />
```

Web Bluetooth API 在 Android WebView 中不被原生支持，移动端智能魔方功能需通过 Capacitor 蓝牙插件（如 `@capacitor-community/bluetooth-le`）或自定义原生桥接实现。当前未接入。

## 12. 踩坑记录与经验总结

### 12.1 BLE 连接类

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| GATT `connect()` hang 住 | BLE 适配器忙或刚断开时既不 resolve 也不 reject | 所有 GATT 操作加超时（`_withTimeout`），connect/getServices 8s |
| 页面刷新后首次连接失败 | BLE 适配器未就绪 | 延迟 500ms 重试一次 |
| `getPrimaryServices()` 连接后仍失败 | 连接不稳定，需重试整个流程 | `_connectAndSetupWithRetry` 重试 connect→getServices→setup 全流程 |
| 用户多次点击连接导致竞态 | 多个连接请求并行 | `_connecting` 标志防重入 |
| 断开后立即重连失败 | BLE 适配器未释放 | 断开后等待 500ms 再重连，每次重试前先 disconnect 并等待 300ms |
| `gatt.connect()` 成功后 setup 失败 | 连接不稳定 | 将整个 connect+setup 流程纳入重试，而非仅重试 connect |

### 12.2 协议解析类

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| MOVE 事件与 FACELETS 事件顺序混乱 | 协议设计中 MOVE 和 FACELETS 可能在同一通知包中 | MOVE 缓冲机制：先缓冲 MOVE，FACELETS 到达后统一输出 |
| 缓冲区无限增长 | FACELETS 事件丢失时 MOVE 持续缓冲 | 安全阀：缓冲区超过 50 条时强制输出 |
| 多事件通知解析偏移错误 | `dataLength` 可能为 0 或不可靠 | 回退到固定长度表（`_eventFixedLength`），无法确定时跳出避免死循环 |
| MAC 地址提取错误 | manufacturer data 格式因浏览器而异 | 支持 `DataView` 和 `Map` 两种格式，最后 6 字节倒序 |

### 12.3 3D 渲染类

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 内存泄漏 | Three.js 资源未释放 | `onBeforeUnmount` 中 dispose 所有 geometry/material/renderer，cancelAnimationFrame，停止 TWEEN |
| 动画热路径 GC 压力 | 每帧 `new Vector3/Matrix4/Quaternion` | 模块级预分配临时对象 `_rotAxis/_rotMatrix/_rotQuat` |
| 渲染空闲时浪费 GPU | `requestAnimationFrame` 每帧都 render | 按需渲染：无动画/无交互/无姿态更新时跳过 `renderer.render()` |
| 陀螺仪高频更新导致渲染卡顿 | 每个 GYRO 事件都触发一次姿态更新 | `requestAnimationFrame` 合合同帧多次 GYRO 为一次更新 |
| 转动动画与姿态跟随冲突 | 层转动和整体姿态共用同一 Group | 双层架构：`outerGroup`（姿态）+ `cubeGroup`（层转动）解耦 |
| GAN 坐标系与 Three.js 坐标系不一致 | GAN +Y=B 而 Three +Z=F | `setAttitude` 中映射：GAN X→Three X，GAN Z→Three Y，GAN Y→-Three Z |

### 12.4 部署类

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| Web Bluetooth API 不可用 | 非 HTTPS 环境 | Cloudflare Tunnel 接入 HTTPS（bh6340.me），SSL/TLS 设为 Flexible |
| Capacitor 6+ WebView 拦截 HTTP 请求 | 默认 `https://localhost` 加载 | `capacitor.config.json` 设置 `androidScheme: "http"` |
| 浏览器 Private Network Access 阻止 | 公网域名直接访问 localhost 图片 | 使用 Cloudflare Tunnel 统一域名入口 |
| Cloudflare Error 1033 | Tunnel 未正确路由到 nginx | `docker-compose.yml` 挂载 cloudflared 配置文件，ingress 规则指向 `icube_nginx:80` |
| Cloudflare SSL/TLS Full 模式冲突 | 服务器走 HTTP，Cloudflare 尝试 HTTPS 回源 | SSL/TLS 模式设为 Flexible |
