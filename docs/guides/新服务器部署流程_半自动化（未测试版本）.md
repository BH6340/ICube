> **适用场景**：每月换试用服务器需要从 0 重新部署。对比「全手动版」（见 [服务器部署流程.md](./服务器部署流程.md)），本版用 4 个脚本把 100+ 条手动命令压缩成 **3 条主命令 + 少量交互**。
>
> **当前版本部署状态参考**：HTTP 已部署成功，HTTPS 待后续配置。
>
> **脚本目录**：`scripts/deploy/` 下，共 4 个脚本。

## 脚本一览

| 脚本 | 谁跑 | 频率 | 做什么 | 手动等价步骤数 |
|------|-----|------|-------|--------------|
| `scripts/deploy/deploy_01_init.sh` | **root** | 新服务器跑 1 次 | 系统更新 + 时区 + 建用户 bh + 装 Docker + 镜像加速 + 开机自启 | ~30 条 |
| `scripts/deploy/deploy_02_app.sh` | **bh** | 新服务器跑 1 次 | SSH key 生成/认证 + git clone + 交互式填 IP/域名 + **自动生成 SECRET_KEY** + 启容器 + 验 HTTP | ~50 条 |

| `scripts/deploy/deploy_update.sh` | **bh** | 更新代码时用 | git pull + 自动判断改了前端/后端/迁移/静态 + 选择性 rebuild + 重启 | ~10 条 |

## 前置条件

1. **一台服务器**：2核 4G，Ubuntu 22.04 LTS
2. **安全组放行端口**（云服务器控制台做）：22 / 80 / 443 / 3306（3306 可选，生产建议关）
3. **GitHub 仓库地址**（默认用 `git@github.com:BH6340/ICube.git`，可改）
4. **（可选 HTTPS）**：一个已解析到服务器公网 IP 的域名

## 第 1 步：服务器初始化（root 执行，10~20 分钟）

> 💡 这一步做的事：系统更新、时区、建部署用户 bh、装 Docker + 镜像加速 + 开机自启

### 1.1 登录 root 并获取脚本

**情况 A**：服务器上还没 clone 项目（大多数情况）

```bash
# 以 root 身份直接从 GitHub 下载脚本（用 HTTPS raw 地址）
mkdir -p /tmp/deploy
curl -fsSL -o /tmp/deploy/deploy_01_init.sh https://raw.githubusercontent.com/BH6340/ICube/main/scripts/deploy/deploy_01_init.sh
chmod +x /tmp/deploy/deploy_01_init.sh
```

**情况 B**：已经有 ICube 目录（或者你手动把脚本传上去了）

```bash
cd ~/ICube     # 或你存放脚本的地方
chmod +x scripts/deploy/deploy_01_init.sh
```

### 1.2 执行脚本

```bash
bash /tmp/deploy/deploy_01_init.sh
# 如果在 ICube 目录下则： bash scripts/deploy/deploy_01_init.sh
```

运行期间会逐行打印进度（带彩色 ✅ ❌ ⚠️），**出错会立即停止**，然后根据报错排查。

### 1.3 脚本执行完毕后

你会看到这三行提示，**一定要按步骤做**：

```
下一步操作：
  1. 退出 SSH 重新登录（或执行 newgrp docker）让 docker 组生效
  2. 切换用户： su - bh
  3. 执行： bash scripts/deploy/deploy_02_app.sh
```

> ❓ **为什么必须退出 SSH 重新登录？**
>
> `usermod -aG docker bh` 把 bh 加进 docker 组，但**当前登录会话还没刷新**，如果立刻跑 `docker ps` 会报 permission denied。重新登录一次就好了。

## 第 2 步：部署应用（bh 执行，10~20 分钟，含镜像构建）

> 💡 这一步做的事：**SSH key 自动生成 + 提示粘贴到 GitHub** → git clone → 交互式填 IP/域名 → **自动生成 SECRET_KEY**（Python3 → openssl → urandom 三级兜底，**不会再遇到 bash `!@#` 报错**） → 写 .env → 启容器 → 验 HTTP

### 2.1 确认身份并进入脚本目录

```bash
# 确认你是 bh 用户，不是 root
whoami        # 应该输出 bh

# 情况 A：上一步成功后，项目还没 clone，脚本用 /tmp/deploy/deploy_02_app.sh
# （如果没有脚本，先下载）
ls /tmp/deploy/deploy_02_app.sh || {
  curl -fsSL -o /tmp/deploy/deploy_02_app.sh https://raw.githubusercontent.com/BH6340/ICube/main/scripts/deploy/deploy_02_app.sh
  chmod +x /tmp/deploy/deploy_02_app.sh
}

# 情况 B：脚本在 ICube/scripts/deploy/ 下
# chmod +x ~/ICube/scripts/deploy/deploy_02_app.sh
```

### 2.2 执行脚本

```bash
bash /tmp/deploy/deploy_02_app.sh
# 或：bash ~/ICube/scripts/deploy/deploy_02_app.sh
```

### 2.3 脚本中的交互点（3-5 个，看实际情况）

按脚本运行顺序列出：

| 交互节点 | 输入内容 | 说明 |
|---------|---------|------|
| `请输入服务器公网 IP（例如 103.100.211.146）` | 如 `103.100.211.146` | 必填，用于 `ALLOWED_HOSTS` |
| `请输入域名（没有就直接回车）` | 没有直接回车 | HTTPS 时填也可以 |
| **SSH Key 提示**（如有） | 复制下方公钥贴到 GitHub，然后**按回车** | 脚本会自动尝试 ssh -T 验证，最多重试 5 次 |

> 💡 **SSH key 每月都要重新生成吗？**
>
> **不必！** 只要这台服务器重装了才会没有。换服务器装系统会丢失，但同一台服务器上 `~/.ssh/id_ed25519.pub` 是持久化的，下一次跑脚本会检测到并跳过生成。
>
> 如果你想"每月都不用重新加公钥"，可以每月**先在本地生成好一把 SSH key（在你自己电脑上）**，然后 `ssh-copy-id` 或手动贴私钥到新服务器，这样 GitHub 上只要加一次永久的公钥就行。

### 2.4 成功后的输出

```
✅ 第 2 步应用部署完成！

浏览器访问地址：
  前台首页：  http://103.100.211.146/
  后台管理：  http://103.100.211.146/admin/
  登录接口：  http://103.100.211.146/api/users/login/
```

## 第 3 步：配置 HTTPS（root 执行，有域名时再做）

> 💡 先用 HTTP 跑通再上 HTTPS，改动极小。没域名直接跳过此步。

### 3.1 前置条件

- 有域名，且域名 A 记录已解析到服务器公网 IP（可用 `ping 你的域名` 看 IP 是否正确）
- 安全组 80 和 443 端口已放行

### 3.2 执行脚本

```bash
# 切到 root
su - root

# 执行脚本（同样两种情况，挑一种）
bash /tmp/deploy/deploy_03_https.sh
# 或：bash ~bh/ICube/scripts/deploy/deploy_03_https.sh
```

### 3.3 交互点

| 交互节点 | 输入内容 |
|---------|---------|
| `请输入域名（必须已解析到本服务器公网 IP）` | 如 `icube.example.com` |
| `请输入你的邮箱（Let's Encrypt 用于续期提醒）` | 你常用邮箱 |

脚本内部流程：
1. 自动验证域名解析（用 `dig`/`nslookup`，解析不对会提醒但允许你继续）
2. **临时停掉 Nginx 容器** 释放 80 端口
3. Certbot `--standalone` 模式申请证书（Certbot 自己启小 HTTP Server）
4. 复制证书到 `ICube/nginx/ssl/` 挂载目录
5. 写最终的 HTTPS Nginx 配置（HTTP 自动 301 跳转 HTTPS + 443 SSL 监听）
6. 写 `/etc/letsencrypt/renewal-hooks/deploy/deploy-icube.sh` 自动续期钩子
7. 启动 Nginx 容器 + 本地 HTTPS 验证

### 3.4 成功输出

```
✅ 第 3 步 HTTPS 配置完成！

浏览器访问地址：
  https://你的域名/

💡 别忘了更新 .env 中 SERVER_HOST 为 https:// 前缀（如需）
💡 证书 90 天到期，certbot 已配置 systemd timer 自动续期，并重启 Nginx
```

## 日常更新：拉代码 + 自动重启

> 💡 用 `deploy_update.sh`，替代原来的手动 `git pull + 一堆 restart/rebuild`

### 执行

```bash
su - bh       # 切换到 bh 用户
cd ~/ICube
chmod +x scripts/deploy/deploy_update.sh   # 首次需要
bash scripts/deploy/deploy_update.sh
```

### 脚本做的事

| 动作 | 触发条件 | 说明 |
|------|---------|------|
| `git pull` | 每次 | 如果有本地未提交改动，会问是否 `reset --hard` 强制覆盖 |
| `rebuild front` | `cube_front/` 有改动 | 交互式询问，建议选 y |
| `docker compose up -d` | `docker-compose.yml` 有改动 | 应用新的 compose 配置 |
| `restart nginx` | `nginx/` 目录有改动 | |
| `migrate` | 检测到 `migrations/` 文件变更 | 幂等，没变更只跑 collectstatic |
| `collectstatic` | 每次 | 幂等，没变更只花几秒 |
| `restart api` | 后端或 compose 有改动 | 否则 Gunicorn `--reload` 也能生效 |

更新完成后可选看最近 30 行 api 日志。

## 常见问题 FAQ

### 1. `docker: permission denied`

跑完 `deploy_01_init.sh` 后**没有退出 SSH 重新登录**。解决：

```bash
# 退出 SSH 再连，或者 bh 用户执行：
newgrp docker
```

### 2. SECRET_KEY 生成报错 `bash: !@#: event not found`

**不会再发生**——`deploy_02_app.sh` 里 `-c` 后的代码用**单引号**包裹，bash 不会把 `!` 当成历史扩展。而且优先用 `secrets.token_urlsafe`（字符集里不含特殊符号，更安全）。

### 3. `git@github.com: Permission denied (publickey)`

SSH key 没添加到 GitHub，`deploy_02_app.sh` 会自动打印公钥并提示，按提示贴好后回车即可。如果仍失败，用 `ssh -vvvT git@github.com` 手动排查。

### 4. 宿主机 Python 3.10，项目用 3.13，会不会有问题？

**完全不影响**。Docker 环境隔离，Django 跑在容器 `python:3.13-slim` 镜像里，和宿主机 Python 没关系。宿主机 Python 只是脚本里用来生成 SECRET_KEY 的工具而已，版本无关。

### 5. 日志里显示 `Environment: development` 而不是 production？

说明 `docker-compose.yml` 的 `api` 服务 `environment` 里**没加 `DJANGO_ENV=prod`**。加完后 `docker compose up -d api` 重建即可。影响：日志按开发模式输出、异常暴露敏感信息。

### 6. 每月换服务器，SSH key 都要重新生成 + 贴 GitHub 吗？

- **重装系统就会丢失**，确实要重新生成+添加
- 想省这一步：在你自己电脑上生成一把"永久 SSH key"，每月把 `~/.ssh/id_ed25519` 和 `id_ed25519.pub` 两个文件拷贝到新服务器 `~bh/.ssh/` 目录下（记得 `chmod 600 id_ed25519`），GitHub 不用重复添加

### 7. Django 初始化（migrate/collectstatic/createsuperuser）要手动跑吗？

容器启动时**会自动做**。`deploy_02_app.sh` 最后会再补跑一次 migrate + collectstatic 确保万无一失（重复执行没副作用）。只有 `createsuperuser` 需要手动执行，因为要交互式输入用户名密码邮箱。

### 8. HTTPS 配置完以后可以回退到 HTTP 吗？

可以，备份的 icube.conf 在 `nginx/conf.d/icube.conf.bak.YYYYmmdd_HHMMSS`，还原后 `docker compose restart nginx`。

## 排错速查

> 对应手动版 [服务器部署流程.md](./服务器部署流程.md) 第 10 节的完整版，这里只列高频问题。

### 脚本执行到某一步报错

脚本是 `set -e` 模式（任何命令返回非 0 立即停止）。直接看最后几行红颜色报错信息即可。如果网络问题（apt / curl / docker pull 失败），重试一下脚本（**脚本的幂等设计**：已经做过的步骤，如用户 bh 已存在、SSH key 已存在、Docker 已安装等，都会自动跳过并提示）。

### 容器一直在 Restarting

```bash
cd ~/ICube
docker compose ps            # 看哪个有问题
docker compose logs api --tail=100
docker compose logs db --tail=50
```

常见原因：

| 症状 | 原因 | 解决 |
|------|------|------|
| api 报 `ALLOWED_HOSTS` | .env 里的 ALLOWED_HOSTS 没填对 | `vim ~/ICube/.env` 改完 `docker compose restart api` |
| api 报 找不到 `cube_api.settings.prod` | 代码目录没挂对 | 检查 `docker-compose.yml` 的 volumes |
| db 一直 restart | 密码不对或数据卷损坏 | `docker compose down`（别加 -v）再 up |
| nginx 报 403 首页 | front_dist 卷为空，Vue 没构建 | `docker compose logs front`，手动 `docker compose up -d --build front` |

### 前端能访问但 API 全 404

Nginx 配置里 `location /api/` 路径不对，或 api 容器没起来。验证：

```bash
cd ~/ICube
docker compose exec nginx curl -s -o /dev/null -w '%{http_code}\n' http://icube_api:8000/api/users/login/
```

## 每月快速部署检查清单

> 💡 每月拿到新服务器后，按这个 Checklist 走，约 30 分钟完成。

- [ ] 安全组放行 22 / 80 / 443 / 3306（控制台）
- [ ] root 登录，`bash scripts/deploy/deploy_01_init.sh`
- [ ] 退出 SSH 重连 → `su - bh`
- [ ] `bash scripts/deploy/deploy_02_app.sh` → 交互输入 IP → 公钥贴 GitHub → 回车继续
- [ ] 浏览器访问 `http://服务器IP/` ✅ 正常
- [ ] `cd ~/ICube && docker compose exec api python manage.py createsuperuser`
- [ ] 访问 `http://服务器IP/admin/` 用管理员登录 ✅
- [ ] （有域名时）`su - root` → `bash scripts/deploy/deploy_03_https.sh`
- [ ] （可选）本地私钥上传到 `~bh/.ssh/`，下次不用重新贴公钥
