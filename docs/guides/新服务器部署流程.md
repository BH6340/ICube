## 1. 服务器租用及配置

### 1.1 云服务器 vs 轻量应用服务器

| 维度 | 云服务器（CVM/ECS） | 轻量应用服务器 |
|------|-------------------|-------------------|
| 定位 | 通用计算，面向生产、中大型业务 | 开箱即用，面向个人开发者、中小站点 |
| 计费方式 | 固定带宽（不限流量，超出带宽上限才限速） | 流量包（如 2048G/月，用完停机或加价） |
| 可扩展性 | 强：CPU/内存/带宽/磁盘单独扩缩容 | 弱：套餐固定，只能整体换 |
| 运维复杂度 | 高 | 低 |

本项目 Docker Compose 5 容器架构（MySQL + Redis + Django/Gunicorn + Nginx + Vue 构建产物）内存占用约 1.5~2.0GB，**2核 2G 会 OOM，2核 4G 是舒适线**。

最终选择：**云服务器 2核 4G**。

### 1.2 系统

Ubuntu 22.04 LTS（root / Bh1154406467）

### 1.3 安全组配置

在云控制台安全组中放行以下端口（白名单模式，默认拒绝所有入站）：

| 端口 | 协议 | 用途 |
|------|------|------|
| 22 | TCP | SSH 远程登录 |
| 80 | TCP | HTTP |
| 443 | TCP | HTTPS |
| 3306 | TCP | MySQL（用于远程连接数据库查看数据，**生产环境建议关闭**） |

![安全组配置](C:\Users\Administrator\AppData\Roaming\Typora\typora-user-images\image-20260807085737045.png)

> 💡 **为什么只用安全组，不在服务器内部配 UFW 防火墙？**
>
> 安全组在虚拟网卡层拦截流量，永不丢失，且不会把自己锁在外面。UFW 配错一条规则 SSH 就断了，只能用 VNC 救。云上部署主流做法是靠安全组挡外网，服务器内部不跑 UFW。

## 2. 服务器初始化（root）

### 2.1 系统更新

```bash

```

> 💡 **为什么要系统更新？**
>
> - `apt update`：刷新软件源索引（拿最新"目录"），不做任何安装
> - `apt upgrade`：把已安装的软件升级到最新版本（照目录补系统）
>
> 新服务器镜像可能是半年前的，不更新会有已知 CVE 漏洞、Docker 装不上、依赖冲突等问题。让服务器从干净的、打过补丁的基线开始跑 Docker。

## 3. 安装 Docker & Docker Compose（root）

### 3.1 卸载旧 Docker

```bash
apt remove -y docker docker-engine docker.io containerd runc 2>/dev/null || true
```

### 3.2 安装 Docker 官方 GPG 密钥

```bash
apt install -y ca-certificates gnupg lsb-release
mkdir -p /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | gpg --dearmor -o /etc/apt/keyrings/docker.gpg
```

> 💡 **GPG 密钥是什么用？**
>
> 验证 `apt install docker` 装的是 Docker 官方的真包，不是被人篡改过的假包。
>
> Ubuntu 默认只信任自己的密钥，你新加了 Docker 第三方源，不配 GPG 密钥会报 `NO_PUBKEY` 错误，拒绝安装。
>
> - `--dearmor`：把 ASCII 格式的公钥转成 apt 需要的二进制格式
> - `signed-by=`：明确告诉 apt 验证这个源的包签名时用这把密钥（比全局信任更安全）

### 3.3 添加 Docker 软件源（阿里云镜像加速）

```bash
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://mirrors.aliyun.com/docker-ce/linux/ubuntu \
  $(lsb_release -cs) stable" | tee /etc/apt/sources.list.d/docker.list > /dev/null
```

### 3.4 安装 Docker

```bash
apt update -y
apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
```

### 3.5 配置 Docker 镜像加速

```bash
mkdir -p /etc/docker
cat > /etc/docker/daemon.json << 'EOF'
{
  "registry-mirrors": [
    "https://docker.1ms.run",
    "https://docker.xuanyuan.me",
    "https://hub-mirror.c.163.com"
  ],
  "log-driver": "json-file",

    "max-size": "100m",

EOF
```

### 3.6 启动 Docker 并设为开机自启

```bash

systemctl restart docker
```

### 3.7 把部署用户加入 docker 组


> ```bash

> # 用户名：BH6340
> # 密码：粘贴 Token（GitHub 已不支持密码认证）
> ```

### 4.3 配置环境变量

<!-- ⚠️ 部署时将下面的 IP 替换为你的服务器公网 IP 或域名 -->

```bash
cat > .env << 'EOF'
# ========== 必须修改 ==========
# 允许访问的主机：填服务器公网IP或域名，多个用逗号分隔
# ⚠️ 部署时替换为你的服务器公网 IP
ALLOWED_HOSTS=103.100.211.146,localhost

# 允许的前端跨域来源：填域名或IP
# ⚠️ 部署时替换为你的域名或公网 IP
ALLOWED_ORIGIN=103.100.211.146

# 支付宝回调地址（没接支付宝先随便填，后面改）
# ⚠️ 部署时替换为你的域名或公网 IP
SERVER_HOST=http://103.100.211.146

# ========== 安全配置 ==========
# Django 生产环境 SECRET_KEY（必须改成随机字符串，不能和 dev.py 里的相同）
SECRET_KEY=改成的随机字符串

# 数据库密码（和 docker-compose.yml 里的 MYSQL_PASSWORD 保持一致，默认不用改）
DB_PASSWORD=icube123
EOF
```

> ❓ **SECRET_KEY 不能和 dev.py 中的一样？**
>
> 技术上可以运行，但强烈建议不一样。SECRET_KEY 是 Django 所有签名加密的"根密钥"，保护 JWT 签名、密码重置链接、CSRF Token 等。dev.py 的密钥被提交到了 Git 仓库，等于把生产环境的"总钥匙"公开了，任何人拿到仓库就能伪造管理员登录。
>
> prod.py 中 `SECRET_KEY = os.getenv('SECRET_KEY', SECRET_KEY)` 会优先读环境变量，没读到就 fallback 用 dev.py 里的。所以 **.env 里必须写 SECRET_KEY**。

### 4.4 生成随机 SECRET_KEY

```bash
# ✅ 正确写法：整个 -c 后的代码用单引号，代码内部字符串用双引号
python3 -c 'import secrets; print(secrets.token_urlsafe(50))'

# 或者用最简写法
python3 -c 'import secrets; print("DJANGO_SECRET_KEY=" + "".join(secrets.choice("abcdefghijklmnopqrstuvwxyz0123456789!@#$%^&*(-_=+)") for _ in range(50)))'
```

> ❓ **为什么 `python3 -c "..."` 报 `bash: !@#: event not found`？**
>
> 双引号里的 `!` 是 bash 的历史命令扩展符。解决办法：**整个 `-c` 后的代码用单引号**，代码内部的字符串用双引号，这样 bash 不会解释 `!`。

> ❓ **宿主机 Python 是 3.10，项目用的 3.13，会有影响吗？**
>
> **完全不影响**。Docker 容器环境隔离，Dockerfile 里 `FROM python:3.13-slim` 会拉一个干净的 Python 3.13 镜像，和宿主机的 Python 互不干扰。宿主机的 Python 唯一的作用就是刚才生成 SECRET_KEY——换个能执行 Python 的工具而已。同理，宿主机不需要装 Node.js、MySQL、Redis、Nginx，这些全在各自容器里。

```bash
cd ~/ICube
```

正常情况下 5 个容器都应该是 Up 状态，db 显示 (healthy)：

```
NAME        STATUS                    PORTS
icube_db    Up 2 minutes (healthy)    0.0.0.0:3306->3306/tcp
icube_redis Up 2 minutes              0.0.0.0:6379->6379/tcp
icube_api   Up About a minute         8000/tcp
icube_front Up About a minute         5173/tcp
icube_nginx Up About a minute         0.0.0.0:80->80/tcp
```

> ⚠️ **如果 api 容器日志显示 `Environment: development`**
>
> 说明 `DJANGO_ENV` 环境变量没设置。logger_conf.py 用 `os.getenv('DJANGO_ENV', 'dev')` 判断环境，默认 dev。
>
> 这虽然不影响功能运行，但会导致：
> - 日志按开发模式输出（按级别分文件，而非统一 all.log）
> - `diagnose=True`（异常时会暴露敏感信息）
> - 控制台日志级别为 INFO（生产应为 WARNING）
>
> **修复方法**：在 `docker-compose.yml` 的 api 服务 environment 中添加：
> ```yaml
> environment:
>   - DJANGO_ENV=prod          # ← 添加这一行
>   - DJANGO_SETTINGS_MODULE=cube_api.settings.prod
>   # ... 其余不变
> ```
> 然后 `docker compose up -d api` 重建 api 容器。

> 🚫 **如果有容器一直 Restarting**：用排错命令看日志（见第 10 节）。

## 8. 配置 HTTPS（待后续实施）

> 📌 **当前状态**：尚未配置，先用 HTTP 跑着。后续有域名后可随时加上，改动很小，不影响已运行的服务。
>
> 后面加 HTTPS 只需改 3 处：① Nginx 配置文件 ② 证书文件放到 nginx/ssl/ ③ .env 里的 ALLOWED_ORIGIN / SERVER_HOST 加 https 前缀。改完 `docker compose restart nginx api` 即可。

### 8.1 安装 Certbot（root 执行）

```bash
su - root
apt install -y certbot python3-certbot-nginx
```

### 8.2 申请证书

```bash
# 替换 your_domain.com 为你的真实域名，邮箱也要填真实的（续期提醒）
certbot --nginx \
  -d your_domain.com \
  --email your_email@example.com \
  --agree-tos \
  --no-eff-email \
  --redirect   # HTTP 自动跳转 HTTPS
```

### 8.3 复制证书到容器挂载目录

```bash
cp /etc/letsencrypt/live/your_domain.com/fullchain.pem ~/ICube/nginx/ssl/
cp /etc/letsencrypt/live/your_domain.com/privkey.pem   ~/ICube/nginx/ssl/
chown bh:bh ~/ICube/nginx/ssl/*.pem
```

### 8.4 更新 Nginx 配置为 HTTPS

将 `nginx/conf.d/icube.conf` 替换为：

```nginx
# HTTP → HTTPS 强制跳转
server {
    listen 80;
    server_name your_domain.com;  # ⚠️ 改成你的域名

    # Let's Encrypt 续期认证路径
    location ~ /.well-known/acme-challenge/ {
        root /usr/share/nginx/html;
        allow all;
    }

    location / {
        return 301 https://$host$request_uri;
    }
}

# HTTPS 主配置
server {
    listen 443 ssl http2;
    server_name your_domain.com;  # ⚠️ 改成你的域名

    ssl_certificate     /etc/nginx/ssl/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;
    ssl_prefer_server_ciphers on;
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 10m;

    root /usr/share/nginx/html;
    index index.html;

    location /api/ {
        proxy_pass http://icube_api:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;  # ✅ 告诉 Django 这是 HTTPS 请求
        proxy_connect_timeout 60s;
        proxy_read_timeout 60s;
    }

    location /media/ {
        alias /usr/share/nginx/html/media/;
        expires 30d;
    }

    location /static/ {
        alias /usr/share/nginx/html/static/;
        expires 30d;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }

    access_log /var/log/nginx/icube_access.log;
    error_log /var/log/nginx/icube_error.log;
}
```

### 8.5 重启 Nginx 生效

```bash
cd ~/ICube
docker compose restart nginx
```

### 8.6 证书自动续期

```bash
# 创建续期钩子（续期成功后自动复制证书并重启 Nginx 容器）
cat > /etc/letsencrypt/renewal-hooks/deploy/deploy-icube.sh << 'EOF'

chmod +x /etc/letsencrypt/renewal-hooks/deploy/deploy-icube.sh
certbot renew --dry-run   # 测试续期
```

## 10. 排错命令速查

```bash
cd ~/ICube

# 1. 查看所有容器状态，是否有 Exit / Restarting
docker compose ps

# 2. 查看问题容器的日志
docker compose logs nginx --tail=50
docker compose logs api --tail=200
docker compose logs db --tail=50

# 3. 常见问题诊断：
#   a. Nginx 502 Bad Gateway → Django 没起来，看 api 容器日志
#   b. Django ALLOWED_HOSTS 报错 → 重新填 .env 的 ALLOWED_HOSTS，docker compose restart api
#   c. 403 Forbidden → 静态文件路径权限，或 collectstatic 没跑
#   d. 登录报 401 Unauthorized → 邮箱或密码错误，或用户未注册成功
#   e. 注册报 400 Bad Request → 序列化器验证失败，检查邮箱是否已存在、用户名是否为空

# 4. 进入容器内部排错
docker compose exec api bash         # 进 Django 容器
docker compose exec nginx bash       # 进 Nginx 容器
  # Nginx 容器内常用：
  curl http://icube_api:8000/api/users/login/   # 测容器内能否通 Django
  ls /usr/share/nginx/html/                      # 看前端文件有没有挂载
  ls /usr/share/nginx/html/static/               # 看静态文件有没有收集

# 5. 查看容器网络
docker network inspect icube_icube_network
```

## 11. 踩坑记录

### 11.1 git clone 报 Permission denied (publickey)

**现象**：`git clone git@github.com:BH6340/ICube.git` 报 `Permission denied (publickey)`

**原因**：用 SSH 方式克隆必须配置 SSH key，private 仓库更需要认证身份。

**解决**：在服务器生成 SSH key 并添加到 GitHub（见 4.1 节）。

### 11.2 SECRET_KEY 生成报 bash: event not found

**现象**：`python3 -c "import secrets; print('...!@#...')"` 报 `bash: !@#: event not found`

**原因**：双引号里的 `!` 是 bash 的历史命令扩展符。

**解决**：整个 `-c` 后的代码用单引号包裹，代码内部字符串用双引号。或直接用 `python3 -c 'import secrets; print(secrets.token_urlsafe(50))'`。

### 11.3 日志显示 Environment: development

**现象**：api 容器日志输出 `Environment: development`，而非 production。

**原因**：`docker-compose.yml` 的 api 服务 environment 中没有设置 `DJANGO_ENV=prod`，logger_conf.py 默认 fallback 到 dev。

**影响**：日志按开发模式输出、diagnose=True 暴露敏感信息、控制台日志级别为 INFO。

**解决**：在 docker-compose.yml 的 api environment 中添加 `- DJANGO_ENV=prod`，重建 api 容器。

### 11.4 宿主机 Python 版本差异

**疑问**：宿主机 Python 是 3.10，项目用 3.13，会有影响吗？

**结论**：完全不影响。Docker 容器环境隔离，Dockerfile 里 `FROM python:3.13-slim` 拉的是独立镜像，和宿主机 Python 互不干扰。宿主机只要有 `git` 和 `docker` 两条命令就够部署。

### 11.5 注册登录报错排查

**现象**：部署成功后，注册返回 400 Bad Request，登录返回 401 Unauthorized。

**排查思路**：

- **登录 401**：`authenticate(email=..., password=...)` 返回 None，说明邮箱或密码错误。最常见原因是注册没成功（用户不存在）。
- **注册 400**：序列化器验证失败。检查：
  1. 邮箱是否已注册（UserSerializer 的 email 字段 unique=True）
  2. 用户名是否为空（前端从邮箱 @ 前截取，如果邮箱格式异常可能为空）
  3. 数据库 migrate 是否执行成功（表结构是否存在）

**排查命令**：
```bash
# 进入 Django shell 检查用户
docker compose exec api python manage.py shell
>>> from apps.accounts.models import User
>>> User.objects.all()        # 查看是否有用户
>>> User.objects.create_user(email='test@test.com', password='123456', username='test')
>>> exit()

# 直接用 curl 测试接口
curl -X POST http://127.0.0.1/api/users/register/ \
  -H "Content-Type: application/json" \
  -d '{"user":{"username":"testuser","email":"test@test.com","password":"123456","bio":"test"}}'

curl -X POST http://127.0.0.1/api/users/login/ \
  -H "Content-Type: application/json" \
  -d '{"user":{"email":"test@test.com","password":"123456"}}'
```
